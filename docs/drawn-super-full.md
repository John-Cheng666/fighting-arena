# 杰米 SA3／CA 二维完整演出审阅版

入口：`/drawn-super-full.html`。招式演练选择 SA3 或 CA 后的「查看二维演出完整版」会打开对应影片。旧入口 `/drawn-super-preview.html` 和 `drawn-supers-v1/` 的初版保留，可在完整版页面中返回对照。

本版保留用户认可的二维人物画风，补齐启动、命中主体和恢复动作，提供补帧版与重绘原帧对照。人物固定为实际四酒的披发杰米攻击、零酒束发杰米受击。本页是完整命中演出的独立审阅页，未接入战斗引擎；不声称已完成防御、落空、不同角色组合或 KO 分支。

## 交付内容

所有文件保存在 `public/assets/jamie/drawn-supers-v2/`。

| 影片 | 长度 | 关键帧 | 文件 |
| --- | --- | --- | --- |
| SA3 | 617 帧，约 10.283 秒 | 121 张，含共享启动段 | `sa3-smooth.mp4`、`sa3-drawn.mp4` |
| CA | 712 帧，约 11.867 秒 | 140 张，含共享启动段 | `ca-smooth.mp4`、`ca-drawn.mp4` |
| 两段合辑 | 1329 帧，22.15 秒 | 顺序播放 SA3、CA | `review-full.mp4` |

影片均为 1920×1080、60 FPS、H.264，配 48 kHz 立体声 AAC 日语原声。`smooth` 采用镜头内运动补间；`drawn` 保持重绘画面，每张通常持续五个 60 Hz 帧。后者用于检查实际绘制内容，不将重复画面计为新绘制帧。

独立重绘画面共 244 张，分为 42 张三列两行图集。共享启动段在两段影片中各出现一次，所以每段计数相加为 261。大多数图集为 2048×768，少数边界为 2043／2046 宽或 770 高，逐格裁切使用实际尺寸。每格约 680×380，是初版约 340×190 的两倍线性尺寸、约四倍像素面积。**1080p 是影片输出规格，原始重绘单格并非原生 1080p。** 最终使用 Lanczos 放大，未把单纯放大描述成新增绘制细节。

## 重绘与来源

画面全部由内置 **imagegen** 根据姿势参考重新绘制，没有把原游戏实录或原 3D 预览录像直接拼入成片。`PROMPTS.json` 保存 42 批提示词和原始输出位置；`CORRECTIONS.json` 保存开场两批仅修正披发一致性的编辑记录。原始与修正图集均保留，`artwork.json` 明确选择修正后的两张开场图集。

姿势参考分别来自：

- 启动与 SA3 宽景收尾：项目缓存的 CAPCOM 官方 `reference/603.mp4`，按十二张／秒采样；参考中的束发攻击方和白衣受击方重绘为本版固定的披发／浅金衣人物。
- SA3、CA 命中主体：已有 `cinematic/review-v3.mp4`。该文件是先前用原版模型、动作与镜头转换结果制作的浏览器录像，不是原游戏实录；源录像为 30 FPS，姿势参考的时间精度受该采样约束。
- CA 恢复：已恢复的 `esf021_CAA_GETUGASAIHOU_END` 与 `esf021_CAD_GETUGASAIHOU_END` 动作。临时工具按实际四酒／零酒外观及原参数头发物理采样；末段宽景相机为本次审阅布置，未声称它是原版相机。
- 画风与身份：用户认可的 `drawn-supers-v1/sa3-atlas.png`、官方 `official-jamie.png`。

主体相机跳变位置由已有 `camera.json` 的相机平移变化确定，再映射到五帧绘制间隔。原始动作帧与重绘采样不构成原引擎逐帧无损复现。

## 补帧与时长

三段主要时钟分别为启动 84 帧、SA3 主体 438 帧／恢复 80 帧、CA 主体 499 帧／恢复 114 帧，另加 15 帧收声停格。播放器以影片本身的媒体时钟为准，逐帧按 1／60 秒跳转，不用另一个墙钟驱动画面或声音。

运动补间使用 [FFmpeg 的 minterpolate](https://ffmpeg.org/ffmpeg-filters.html#minterpolate)，每个机位单独处理。硬切边界不做跨镜头补间；画面变化过大的位置保留保守切换。补间在 768×432 的中间画幅执行，之后放大至影片输出尺寸。衣纹、头发或遮挡处仍可能存在细小生成差异或运动估计误差，因此保留原帧版本供审阅。

固定版本的 FFmpeg 在 `setpts` 后会失去供补边使用的帧率信息；构建脚本先恢复 12 FPS，再按帧数补齐前后参考帧。短镜头、单关键帧机位和尾段都按精确 60 Hz 帧数裁切。每个分镜和每部影片都实际解码核对帧数，避免只看容器时长而漏掉空镜头或短段。

合辑连接时另行裁掉 AAC 的编码填充，并锁定 1329 帧，避免连接处多出一帧。独立影片与合辑均通过实际解码检查，解码器不得输出错误。

## 原声

`scripts/prepare-drawn-super-audio.mjs` 从已批准的杰米动作事件、数值接触表和日语个人语音生成 `audio.json`。保留启动 action 1211／1215 在启动区间内的事件，再接捕获 action 1212／1213、1216／1217 的事件；本版包含初版主体节选未覆盖的恢复语音 21339／21349。全程使用 27 个已批准原音频文件，记录逐个 SHA-256，不读取游戏安装。

离线混音复用 `compileAudioTimeline` 的逐角色优先级、避免重复与打断规划，保留原事件内部延迟，未额外制造通用击打声。通过 Web Audio 预览已有的同类增益比例和压缩参数混音；原引擎 Wwise DSP、RTPC、总线策略没有完整复刻。恢复段按已有事件时间轴审阅，未声称所有运行时分支都已与原引擎验证。

画面与声音封装在同一影片中。暂停、回拖、重播、变速、循环和切换版本不会残留旧音源。慢放使用浏览器的保持音高播放；音画同步审阅以 1× 为准。最后两句恢复语音分别约在 10.097／11.249 秒结束，完整影片保留足够的收声时间。

## 播放与审阅

支持播放／暂停、逐帧、0.25／0.5／1×、原声开关、循环、全屏，以及启动／命中／恢复章节跳转。切换原帧和补帧版时保留当前时间位置。两个招式各自从头播放，时长和章节相互独立。空格播放，左右键逐帧，M 切换声音；表单控件保留自身键盘行为。后台标签自动暂停。

可用 `?move=CA&frame=430` 直达关键帧，`?render=drawn` 选择重绘原帧，`?embed=1` 隐藏说明，`?silent=1&autoplay=1` 静音自动播放。

## 重建与核验

普通查看、构建、测试和成品散列核验只使用项目内文件。只有重建影片需要已安装的 FFmpeg；不自动安装它，也不需要游戏、Blender 或图像生成 API。现有生成 PNG 即为重建输入。

```powershell
node scripts/prepare-drawn-super-audio.mjs
node scripts/render-drawn-super-audio.mjs --ffmpeg C:/path/to/ffmpeg.exe
node scripts/build-drawn-super-full.mjs --ffmpeg C:/path/to/ffmpeg.exe
node scripts/finalize-drawn-super-full.mjs
node scripts/finalize-drawn-super-full.mjs --verify --ffmpeg C:/path/to/ffmpeg.exe
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
node node_modules/vite/bin/vite.js build
```

`manifest.json` 固定原画、修正图集、提示词、时间轴、原声清单、影片与海报的尺寸／散列和参考来源。`--verify` 不重写成品，`--ffmpeg` 额外完整解码五部影片并核对 617、712、1329 的帧数。

测试覆盖非整除关键帧边界、启动与主体的切换、两种终结和收声尾段。实际浏览器另检查 1080p 解码、带声播放、暂停、逐帧、章节跳转、版本切换保留位置、声音、慢放、结束、循环、移动端布局与不加载 3D 资源。
