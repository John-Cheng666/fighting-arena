# 角色个人语音接入经验

本文记录杰米日语个人语音从审阅结果落地到工程的过程，供其他角色复用。BGM、SE、接触声和原生帧取证的基础流程见 [角色音频工程指南](character-audio.md)。

本轮范围是日语战斗及选人语音。用户逐条审阅了188段去重试听：保留170段，排除18段，并指定出场、P1/P2战前对白、四档胜利和拆投的用途。原始研究共182份WEM、147个可播放事件、213个展开版本；多个事件可能共用同一段PCM，不能把这些数目都称为“台词数”。

## 工程入口与数据职责

| 位置 | 职责 |
| --- | --- |
| `scripts/sync-sf6-voices.mjs` | 读取最终审阅、核对SHA、复制保留音频、删除本生成器已校验且被淘汰的旧文件、生成路由与来源记录 |
| `src/content/audio/catalog.json` 的 `voices[characterId]` | 角色独立的请求池、优先级、跳过参数、避免重复、场景角色和胜利档位 |
| `src/characters/jamie/data/audio.json` 的 `actions[].voiceCues[styleId]` | 原始零起帧VoiceKey；`contacts[].voiceId` 来自原生接触表 |
| `src/characters/jamie/audio.ts` | 将本角色实际行动、分支和接触转成 `voice` / `voice-stop` 事件 |
| `src/view/audio/VoiceDirector.ts` | 角色无关的随机选择、去重、优先级和声音所有权，不读取杰米动作或酒级 |
| `src/view/audio/BattleAudio.ts` | Web Audio节点、预加载、暂停、静音、重开和异步解码生命周期 |
| `src/runtime/OpeningSequence.ts` | 使用独立演出时间组织入场及战前对白 |
| `src/runtime/BattleRuntime.ts` | UI开场、跳过、战斗结束、KO和获胜方语音的衔接 |
| `public/assets/audio/sources.json` | 当前成品SHA、审阅身份、排除项、旧意见覆盖与还原边界 |

所有成品音频都在 `public/assets/audio/`，客户端只读取项目内的JSON及音频。普通安装、构建、部署和测试不需要原版SF6、REA、IDA、wwiser或FFmpeg。

当前项目只有杰米，默认预热全部短声音与所选BGM。扩展多角色阵容后，应利用 `warmup(clipIds)` 仅收集参战角色需要的效果音和语音，避免一次解码整个角色库。

```powershell
npm.cmd ci
npm.cmd run verify:audio
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

Windows PowerShell可能优先解析到受执行策略限制的 `npm.ps1`；使用 `npm.cmd` 即可，不需要修改机器的执行策略。

## 审阅意见是资产级约束

首先验证输入的 `kind/version/language`、所有assetId、音频SHA、PCM SHA、采样帧数、语言事件ID，以及 `items` 与 `assets` 是否一致。未处理、需要调整和明确拒绝是不同状态，不能一律当保留。

本次导入源文件 SHA-256 为：

```text
e442dabc2f246d2ad5d4cf4fc9532d16319ce2d946fbb898059791f6cac3c7c2
```

原始导出与最初待审状态不回写。完整结果和170份原字节文件归档在研究目录 `voice-review-v1/reviewed/<审阅SHA>/`，当前选用由 `selected-manifest.json`、`routing-spec.json` 和 `approval.json` 指向。输入导出中的 `implementationApproved:false` 是当时的静态导出记录；随后用户明确要求工程实现，工程来源清单另行记录这次授权，不伪造原导出历史。

一个去重音频可能对应多个请求。用户拒绝一段声音时，必须从它的全部共享用途移除，而非只删除当前标签下的一个引用。本次拒绝的轻攻击样本此前曾被批准；最新意见覆盖旧意见，旧 `voice-light` 文件、固定占位路由及所有共享候选引用均被清理。轻攻击池保留另外三段已通过的声音，整池均被拒绝的720/721等17个请求没有替代或回退音。

生成器只删除已记录来源、SHA匹配且没有SE/BGM引用的旧成品。它拒绝删除被人工改动的文件，不进行目录递归清空。新保留文件按审阅字节复制，不重新编码；Ogg重新编码即使听感相同，也可能因serial等变化产生新SHA。

## 语言、音源与用途分别取证

日语身份由原始 `EventId_Jpn` 字段和日语媒体银行共同确认。文件名、`_j`/`_e`后缀以及名称哈希都不足以单独证明语言：本次确实遇到看似英语名称、实际连接日语事件的碰撞提示。

按 `VoiceRequestData → TriggerId → EventId_Jpn → bank graph → media` 连接用途。SE和Voice的相同数字ID属于不同命名空间。`TriggerPartsType.Voice=0`、`VoiceStory=1` 区分原生请求类型，Type0不等于“普通攻击喊声”。

展开随机分支使用 `-gra`，保留延迟使用 `-gwd`，保留去重后可能被省略的事件使用 `-gd`。先完整解码原事件，再按实际PCM去重，保留每段音频的全部别名。没有TXTP也不能立即归类为停止或丢失：本次3个事件是Play action连接到没有子节点的随机容器。

研究页的用途标签不冒充字幕或原句翻译。个人演出1498/1499、部分公共请求以及原版对手选择规则没有执行证据时保留未知；用户在审阅中指定的项目用途单独记录。例如选人原音源被指定用于入场，710的两个版本被指定用于拆投。

## 两个时钟与两类随机数

战斗VoiceKey沿用角色真实行动时钟：普通行动、冻结intro、捕获和落地分别适配，不能用 `setTimeout` 或“招式播放百分比”替代。当前宿主普通行动与原始零起帧之间的加减一规则见基础指南。

入场和战前对白走 `OpeningSequence` 的演出时间。UI调用 `startWithOpening()`，内核保持ready；AI、战斗tick和回合计时都不运行。脚本与训练仍可直接调用 `start()`；招式演练不播放整局开场或胜利对白。

当前开场只依次播放P1主动发言、P2回应，不播放入场语音；`entrance`素材仍保留在已审阅资源中。长度来自实际声音元信息，段间留80ms演出间隔。这是本项目的节奏选择，不声称是原作精确时序。开场不随0.25×/4×战斗速度缩放，也不拉伸声音；暂停同时冻结演出时间和AudioContext，跳过取消当前及尚未完成解码的开场语音。

`OpeningSequence`仍支持入场阶段，其位移只修改Phaser显示容器及传给绘制器的显示快照，不改战斗位置、朝向或速度；当前默认开场不安排这一阶段。减少动态效果偏好下避免入场滑动。P1/P2表示玩家槽位，不能依据人物在屏幕左边还是右边选择台词。

语音随机数独立于战斗AI。`VoiceDirector`使用以对局seed、characterId和fighterId派生的独立序列；拒绝语音、改变音量、静音或加减随机版本都不能消耗AI的random。重开重置语音历史，同一seed可以复现选择。不同人物各自维护避免重复历史与声音所有权。

同一个原生随机容器的多个请求别名共用避免重复历史，例如500/510；否则分别按请求维护历史仍可能连续播放同一声音。异步所有权token在reset之后也不重复使用，防止旧onended回调误释放新声音。

## 请求仲裁与中断生命周期

`voice`事件只表达“哪个人物、哪个请求/场景、何时、属于哪个行动”。播放器根据该人物的请求池选声音；没有请求池时安静退出，不借用杰米或另一请求的片段。

本项目采用以下明确的宿主策略：

- 保留每个请求自己的SkipRate。500/501/502/720/721原表约为0.33，其他已定义请求为0；工程按跳过概率解释该字段，原作的完整决策路径尚未运行验证。
- 每名人物同时保留一个主要语音声明。高优先级覆盖低优先级；同优先级的 `prioritizeFirst` 可保留先发声音。不同人物的声音互不抢占。场景台词作为强制演出请求处理。
- 原Limit、ReleaseTime、priority与avoid-repeat均保留。原表Limit0不能理解成静音；当前人物级单语音上限是宿主适配，并不宣称复刻Wwise的所有每触发器限制。
- 从保留版本中选择并避免刚播放的版本。只保留一个版本时不会因避免重复而永远无声。
- 当前构建 `SET_ACTION=3`，`NONE=4`。只有标记随行动停止的语音在行动结束或分支更换时取消，DEFAULT允许保留自然尾响。

当前在未被避免的保留片段中等概率选择。若新角色的原bank显示不等权重或特殊shuffle规则，应先扩展数据合同与测试，不把此处的均匀选择宣称为原版权重还原。

异步decode开始前就要登记优先级声明和所有权token。更高优先级到来、静音、重开、跳过或dispose时，使旧token失效；旧decode即使稍后成功，也不能重新播放或删除新声明。直接取消语音的方法在AudioContext已暂停时也必须有效，不能把“暂停时不消费事件”当作取消成功。

本轮真实浏览器还发现：`resume()`返回Promise，宿主取消暂停时，AudioContext未必已经运行。如果此间继续推进战斗并取走finished事件，播放器会丢掉只发一次的胜利语音。runtime现在把音频处于blocked/恢复中的时间作为短暂就绪屏障，保留尚未取出的事件，也不累计待追赶的墙钟时间；完成恢复后再推进战斗和开场演出。

在倍速战斗中只改变请求间隔，音源 `playbackRate` 仍为1。快节奏下请求会被跳过、覆盖或仲裁；不要让台词积压成战斗结束后仍然朗读的队列。

## 接触、拆投和胜利规则

受击请求读取攻击接触表的原生Voice字段，不能按造成伤害大小猜轻中重。无伤抓取闩锁、ignored接触与普通防御不自动发受伤声。致死接触不叠加普通受伤声，runtime在真实death事件上发KO请求；当前按终局以及吹飞/倒地状态选择本项目适用的原生KO分类。

精准格挡、Drive破防/眩晕起始、实际退出burnout的恢复语音在各自状态转换触发。拆投使用成功拆投处理入口，发给拆投方710请求，两个保留版本沿用避免连续重复规则。原作特有而宿主尚未模拟的受击状态仍保留素材和数据，不从名字或伤害阈值虚构触发。

胜利只对非演练对局的获胜方发一次；平局没有胜利台词。使用未四舍五入的 `hp / maxHp`，而不是UI显示百分比：

| 获胜方剩余血量 | 用户指定场景 |
| --- | --- |
| 100% | 完胜01 |
| 80%（含）至100%以下 | 优胜02 |
| 25%（含）至80%以下 | 小胜03 |
| 25%以下 | 惨胜04 |

这套规则来自用户审阅，独立于“任意一方≤25%触发残血BGM”的规则。它不是原版胜利动作选择器的逆向证明。

## 生成、验证及接下一个角色

仅重新同步个人语音时：

```powershell
$env:SF6_AUDIO_RESEARCH = 'D:\research\sf6-audio'
npm.cmd run sync:sf6-voices
npm.cmd run verify:audio
```

研究包保留 `voice-review-v1/reviewed/<SHA>/audio` 后可以迁移；生成器优先使用当前研究根目录的归档，不依赖manifest中研究机器的旧绝对路径。完整SE/BGM同步发现最终语音审阅后也会调用语音同步，防止再次生成已被拒绝的旧占位。

实现其他角色时按此顺序：

1. 固定该角色、语言及构建，验证bank媒体和请求链，展开随机版本。
2. 完成逐条审阅，记录共享音源的拒绝传播、旧意见覆盖和项目场景用途。
3. 建立自己的请求池、样式VoiceKey和接触Voice字段；用角色ID命名成品。当前同步脚本中的杰米研究入口需要替换为该角色的已审阅资料。
4. 在角色适配器发通用事件；让 `VoiceDirector` 和 `BattleAudio` 继续保持角色无关。
5. 提供角色的entrance、prefight-p1/p2、胜利角色及其档位。没有场景素材就跳过该段，不用另一角色补齐。
6. 测试冻结intro、取消/命中/打空、捕获双方、受击与拆投，再测试暂停、跳过、静音、重开和慢decode竞态。
7. 检查打开或关闭语音后战斗结果不变、旧拒绝SHA没有出现在成品、部署可脱离研究目录，并在实际浏览器观察非零PCM与源节点速率。

关键回归位于 `VoiceDirector.test.ts`、`BattleAudio.test.ts`、`BattleRuntime.voices.test.ts`、`characters/jamie/__tests__/voices.test.ts`。本轮全量429项测试通过；成品共428个音频，包含170段已批准个人语音。真实Chrome的18项检查通过，包含非零PCM、原速播放、对白顺序与四档胜利。实际浏览器验证记录保留在研究目录 `voice-runtime-browser/verification.json`。

原版SF6的RTPC、DSP、精确空间化、所有场景条件和原生仲裁尚未与游戏录音逐项对照。文档和来源清单分别标记源数据、用户规格与宿主适配，不能把本项目测试通过写成“已完全复现原版”。
