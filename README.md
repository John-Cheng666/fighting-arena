# Fighting Arena

React + TypeScript + Vite + Phaser 的自动格斗实验场。默认 **1P 杰米 vs 2P 杰米**，保留现有竞技场视角，集中还原战斗帧、资源、取消和 STANDARD CPU 行为。当前可用角色只有杰米；旧角色的逻辑、选项、音效分支和人物合图已移除。

## 启动与使用

请先安装 Node.js 和 pnpm 10.34.6（版本由 `package.json` 的 `packageManager` 字段固定）。

```powershell
pnpm.cmd install --frozen-lockfile
pnpm.cmd run dev
```

打开终端显示的本地地址。也可运行 `powershell -ExecutionPolicy Bypass -File scripts/dev.ps1`。

在「对局配置 → 参赛选手」中展开「调整选手参数」，分别调整 CPU 1–8、初始生命、伤害倍率、酒级、Drive 和 SA。两席位独立保存；修改一方并重开会保留另一方配置。切换角色后再切回来，保留该席位先前的角色设置。默认生命 10000、伤害倍率 1、Drive 6、SA 0、酒级 0；原版杰米仅有默认 STANDARD 风格，不再提供自编的压制／饮酒风格。

「对局配置 → 对局规则」只管理回合时间和随机种子。「招式演练」通过角色自己的演练插件执行命中、防御、落空场景，并复用实际出招、资源、派生和取消校验。空格暂停，R 重开，M 切换声音；支持 0.25／0.5／1／2／4 倍速和舞台切换。

声音默认关闭，点击扬声器或按 M 启用已审阅的《街霸6》原事件音频。竞技场的「声音设置」可选择随舞台配乐或统一杰米主题，分别调节音乐、音效和可选日语语音。任意一方生命不高于25%时切换残血变奏；演练默认使用训练场配乐。首次准备声音时暂缓战斗步进，完成后继续；慢放只改变事件触发间隔，声音本身保持原速。

竞技场下方的独立「对局记录」区域保存本局全部事件，支持按来源、事件类型和招式搜索、分页查看与伤害来源汇总。伤害逐段记录招式、补正、反击／确反、防御削血、霸体和生命变化，区分结算伤害与实际扣血，并记录回复及捕获收尾的延迟 KO。时间显示为「分:秒.帧」（60 帧/秒）。「导出 JSON」包含双方设置、种子、胜负、结构化日志及原始事件；运行中也可导出。日志保存在当前页面内存中，重开、切换角色或演练、刷新页面后清空，需要留存时请先导出。

进入演练、选择招式或命中／防御／落空情境后先准备场景，点击「开始演练」或「演练所选招式」才播放。播放控制集中在竞技场上方；日志支持暂停列表更新，翻页后固定当前记录，对局仍持续记录新事件。

顶部导航支持 #battle、#training 和 #battle-log，可使用浏览器前进／后退。默认浅色，可切换深色；主题与舞台记住本机选择，对局参数属于当前页面会话。桌面采用双栏工作台，移动端按操作顺序纵向排列。设计规范在 design-system/arena-lab/MASTER.md。

## 角色模块与目录

```text
src/
  engine/                 无角色依赖的固定步内核、接口、通用碰撞与胜负
    ai/                   可复用的 STANDARD 选择与命令解释器
    systems/              移动、弹体、批量伤害结算与胜负
  characters/
    catalog.ts            玩法模块注册入口
    ui.ts                 可选 React 扩展注册入口
    renderers.ts          可选 Phaser 绘制扩展注册入口
    jamie/
      module.ts           生命周期、状态、配置、命中、演练的插件接口
      config.ts           杰米设置字段、默认值和校验
      state.ts, types.ts  角色私有状态
      moves.ts, data/     招式定义、官方帧表与提取的原版 AI 参数
      combat/             出招、资源、取消、补正、捕获与命中规则
      ai/                 原版命令翻译、条件和竞技场输入适配
      training/           杰米演练驱动
      ui/, view/          杰米资源面板、样式与人物绘制
      __tests__/          战斗规则与原版 AI 数据回归
  game/                   注入已安装角色的默认对局与演练入口
  runtime/                播放时钟、每席位配置、不可变摘要与日志
  app/                    通用选手卡片、设置表单、舞台和布局
  view/                   通用场景、绘制接口和音效
  content/                场地内容
```

`engine/Battle` 接收 `CharacterRegistry`，不导入杰米或浏览器库。角色状态存在 `Fighter.characterState: unknown`，由模块自己的访问函数收窄。`p1`／`p2` 是席位，不是角色名；同角色双方不共享资源、冷却或设置。

新增角色时，在 `characters/<id>/` 实现 `CharacterModule`，向 `catalog.ts` 注册。模块提供元信息、设置 schema、校验、初始状态、基础属性、描述和需要的生命周期钩子；状态应可 `structuredClone`。CPU、命中防御、资源、出招和演练由模块负责。可用 `registerCharacterUI`／`registerCharacterRenderer` 添加资源面板与绘制；没有自定义扩展时使用通用面板和基础外形。无需修改战斗内核。

所有角色普通投复用引擎的推开结算：前投释放后间距170、后投240竞技场单位，后投换位一次；贴墙时联合限制双方坐标以保留距离。新角色接入契约、起身抢断回归和原版资源边界见[普通投实现说明](docs/normal-throws.md)。

每个活动模块每帧收到一次 `step`，其中 `actors` 仅含该模块的参战者。通用内核随后移动、检测接触并同时结算伤害，再调用 `afterContacts`、`endFrame` 和胜负判断。命中防御与来源回调分开；双方同帧致命命中可形成平局。独立生命设置的超时胜负按剩余生命比例比较。

```ts
import { Battle } from "./src/game/Battle";

const battle = new Battle({
  seed: 428003,
  roundTimeSeconds: 99,
  fighters: [
    { characterId: "jamie", settings: { cpuLevel: 8, startDrinkLevel: 0 } },
    { characterId: "jamie", settings: { cpuLevel: 3, startDrinkLevel: 2 } },
  ],
});
battle.start();
battle.step();
```

设置中省略的字段由各角色填入默认值。内核没有全局角色生命、伤害或 CPU 参数。

## 原版 STANDARD AI 的来源与执行

本机 Steam Build `25071972`，`StreetFighter6.exe` SHA-256：`26095ad815bca8c58205814348315f132e74a74650c63fe1b2801c752643627c`。通过 REA／IDA、TDB71 与此前保存的运行时元数据核查控制流；本轮只读访问包目录和命中资源，未启动游戏。

从本机 `re_chunk_000.pak` 精确提取 `natives/stm/product/charparam/esf/esf021/ai/esf021standardai.user.2`。解压资源 483240 字节，SHA-256：`0247c3a38e7e410bdcf92bd2e6d887596418a82d428ebc529d79080440e6b1d5`。解码 9108 个 RSZ 对象、1821 行参数、323 个原始分支组，读取恰好到 EOF；引用、字段类型和填充校验通过。来源和脚本保存在 `research/sf6-ai/fidelity/`，运行数据在 `characters/jamie/data/standard-ai.json`。

解释器已接入原始八级概率／冷却、三列条件和 UniqueParam、命令字符串、按钮编码、构造函数里的 26 项局势优先序，以及单情境／忽略空情境配置。保留原生的根表风格 0 回退、分支独立权重、按情境编号收集、浮点单精度累计、uint16 包含边界的抽签、命令随机时长、循环次数、分支终止与帧末冷却语义。还按难度重建可用分支：低难度引用不存在分支而原生编译失败的项目，在输出前排除，不等到执行后才失败。

方向和按键逐帧输出，经 `ai/input.ts` 的输入历史识别后请求实际招式；即使招式不合法，原版按键指令也按自己的持续时间推进。碰撞后继续同一命令程序，保留一帧取消窗口。演练禁用自动 CPU。

CPU 输入支持本地原版超必杀的 `23626`／`21424` 简化指令。Parry 松键与公开释放接口共用逻辑，持续精准格挡会反馈给 `AJST` 条件；普通投捕获进入原版被投情境并允许合法拆投，后跳／原地跳保留各自的方向观测。

原版 AI 的距离分档先换算为竞技场尺度，使近身脚本的距离上限落在最短地面普通技射程内，并留出 6 像素余量；原始距离阈值、概率与冷却表保持原值。前走会减小地面纵向错位并接近横向出招位置，侧墙处选择场内可用的一侧。命中和瞄准仍使用真实二维距离，反应局势仍使用竞技场距离；这项换算属于本模拟器的空间适配。

**还原边界：**原版 AI 参数、解析语法和已核控制流程有本机静态证据；世界状态仍来自本模拟器。空间范围、运动轨迹、部分战况判断、输入缓冲与 RNG 使用竞技场适配，尚未用原游戏实际对局逐帧对齐。开场世界停止、捕获动作时钟与 `TIMER_STOP` 回合计时已分开；逐角色 hitstop 调度和少数 `DoWorld` 程序仍未完整复刻。

## 本地战斗数值基线

`src/characters/jamie/data/native-numerics.json` 来自同一已安装版本的 `021.fchar.18`，资源 SHA-256 为 `2e530707b0dceb86921937bcd72e3f6f89d828c7bf310f2da289e0c3bc0a354f`。数据包含 101 行动作映射、逐击接触值、捕获序列和状态事件；本地资源优先于独立更新的官网帧表。详细来源、当前二进制复核与尚未建立的规则见 `research/sf6-alignment/findings.zh-CN.md`。

- 默认生命 10000、伤害倍率 1、Drive 上限 60000、SA 上限 30000。测试中的 1500 生命与小伤害倍率是显式测试配置。
- 伤害逐击结算，按原版 Q32 比例保留中间精度，最终截断百分比和每次伤害。酒级攻击系数为 90/95/100/105/110%；SA2 为 105%，期间不增长 SA。原始 SA1／饮酒分支／SA3／CA 总伤害为 2200／1850／2600／4500，实际伤害另受酒级、补正与设置影响。
- 自动受击 SA 收益取该击攻击方原始收益的 70%，格挡为 50%；原始 `65535` 自动值不直接发放。OD／Drive 的启动门槛与消耗量分开，OD 派生不会重复扣启动费用。
- Drive 采用有符号恢复等待；普通地面恢复 40／帧、空中 20／帧，Burnout 地面 50／帧。前走与受伤状态使用对应倍率，耗尽后逐步恢复至上限，再按状态退出 Burnout。可恢复生命等待 120 帧，随后每帧恢复 2。
- SA2 开场世界停止 124 帧，原始动作第 78 帧进入安装、第 111 帧恢复 Drive，安装持续 900 个普通状态更新。SA3／CA 捕获动作采用本地逐击时刻和 448／554 帧动作长度；回合计时分别读取世界停止与原始 `TIMER_STOP` 区间。
- 1× 使用 60 Hz 固定步长。慢渲染帧的剩余时间保留在累积器内；倍速改变播放速率，不改变战斗规则或 CPU 冷却表。

普通投的拆投窗口由本地 6 帧接触停顿与 3 帧 `THROW_ESCAPE` 标志静态映射为 `[0,9)`；端点尚未用原版实战采样。成功后的 14 帧恢复仍是明确保留的竞技场适配值。精准格挡响应动作、完整姿势表继承、逐角色停顿调度和原版 3D 碰撞仍有适配边界。

## 战斗与素材

保留官方帧表所列的酒级门槛、分段有效帧、恢复、普通技帧差、资源消耗、派生、命中／防御取消、补正、Parry、DI 霸体、Burnout、起身、拆投、跳跃惯性与穿身判断。SA3 与 CA 有各自收尾；伤害逐段结算，捕获与胜负收尾共用真实战斗路径。

官网头像、帧表和 28 段原始参考视频的来源与 SHA 记录在 `public/assets/jamie/` 和角色 `data/`。人物使用本项目的二维姿势图集；它们不是原作模型或动画。战斗接触与捕获伤害使用本地资源时刻，二维姿势和镜头仍为竞技场绘制。原作完整 hitbox、骨骼动画、世界巡游／教学等语音银行和横版镜头尚未导入。

已批准的 BGM、动作声、必杀技、超必杀、接触反馈和170段日语个人语音保存在 `public/assets/audio/`，来源与输出散列见其中的 `sources.json`。运行时语音覆盖P1/P2开场、行动喊声、受击、拆投及四档胜利；开场只播放P1开场白和P2回应，可暂停或跳过，战斗计时在演出结束后开始。入场素材保留供后续使用。杰米普通前投命中后，未满4酒时会自动派生喝一口，并播放完整收尾音效与语音。运行时根据实际行动帧、命中、防御和捕获分支触发独立声音，未使用假定全命中的整招试听混音。构建和部署不读取原游戏、REA 或研究目录。

其他角色的资产取证、提取、时钟映射、接入接口、验证步骤及已知还原边界，见 [角色音频工程指南](docs/character-audio.md)。`pnpm.cmd run verify:audio` 可独立核验所有音频文件和引用；只有重新生成资产时才需准备指南列出的本地提取资料并运行 `pnpm.cmd run sync:sf6-audio`。

个人语音的审阅覆盖、独立随机数、优先级、动作中断、开场时钟和后续角色接入步骤，见 [角色个人语音接入经验](docs/character-voice.md)。`pnpm.cmd run sync:sf6-voices` 只同步已确认的个人语音，不重新编码或重新提取原版资源。

## 验证

```powershell
pnpm.cmd run typecheck
pnpm.cmd run verify:audio
pnpm.cmd test
pnpm.cmd run inspect:jamie
pnpm.cmd run inspect:jamie-variants
pnpm.cmd run inspect:jamie-spacing
pnpm.cmd run inspect:standard-ai
pnpm.cmd run sync:jamie-numerics
pnpm.cmd run build
```

`inspect:jamie` 运行 30 场不同 CPU／酒级配置；`inspect:standard-ai` 运行八档 CPU × 三种初始酒级 × 两个种子的 48 场对局。检查终局、有限坐标、生命、资源、冷却和冻结边界，报告写入 `research/`。`inspect:jamie-variants` 执行 118 个变体的 354 个演练场景。它们是模拟器集成验证，不代表原游戏行为一致性验证。

`inspect:jamie-spacing` 运行 CPU 6／8 × 两个种子 × 12 种站位的 48 场完整对局，覆盖上下换位、四向斜线、侧墙和纵向远距离。检查有效接触、最长无接触间隔、坐标边界和终局，报告写入 `research/jamie-spacing-validation.json`。

`scripts/sync-jamie-ai.mjs` 与 `scripts/sync-jamie-numerics.mjs` 只从已有研究 JSON 生成精简运行数据，不读取游戏安装目录。普通启动、测试和构建均不需要本机安装街霸 6。
